## 三、入口层：命令是怎么路由的？

### 入口文件链路

```text
用户输入: mirajay-cli create my-app
         │
         ▼
    bin/cli.mjs       ← #!/usr/bin/env node（告诉系统用 Node 执行）
         │
         │  import('../dist/index.js')
         ▼
    src/index.ts      ← 编译后的入口
         │
         │  runMain(main)  ← citty 启动命令路由
         ▼
    citty 引擎        ← 解析命令名 "create"
         │
         │  匹配 subCommands.create → init 命令
         ▼
    src/commands/init.ts  ← 执行 init 的 run() 方法
```

### 命令注册方式

在 `src/index.ts` 中，所有命令通过 citty 的 `defineCommand` 定义，然后注册为子命令：

```ts
const main = defineCommand({
  meta: {
    name: 'mirajay-cli',
    version: '1.0.0',
    description: '企业级前端脚手架',
  },
  subCommands: {
    init,           // init / create 都指向这个
    create: init,   // create 是 init 的别名
    lint,
    build,
    doctor,
    test,
    commit,
    deploy,
    upgrade,
    'update-deps': updateDeps,
  },
  run() {
    banner()
    console.log('使用 mirajay-cli --help 查看可用命令')
  },
})
```

> **什么是 citty？**
> citty 是 unjs 生态的命令行框架。你只需要用 `defineCommand` 定义命令的元信息（名称、描述、参数）和执行函数（`run`），citty 就帮你处理参数解析、帮助信息生成、子命令路由等。类似于 React 里用 `defineComponent` 定义组件。

## 四、命令层：init 命令的编排逻辑

`init.ts`（也叫 `create`）是最复杂的命令。它的执行流程是一个清晰的流水线：

```text
init 命令执行流程
═══════════════════════════════════════════════════

 1. 打印 Banner
    │
 2. 加载配置 (.clirc)
    │
 3. 交互式问答 (或 -y 默认配置)
    │  → 项目类型 → 框架 → UI库 → CSS → 工程化 → 包管理器 → Git
    │
 4. 校验用户输入 (白名单校验)
    │
 5. 确定目标目录
    │
 6. [Flutter] 检测 Flutter SDK
    │
 7. 触发 init:before 钩子 (插件可在此介入)
    │
 8. 解析模板名称 (根据用户选择确定用哪个模板)
    │
 9. ★ 生成项目 (核心！)
    │  ├── 渲染业务模板 (desktop-vue / mobile-taro / ...)
    │  ├── [Monorepo] 渲染 monorepo-base 布局
    │  ├── 合并 engineering-base 工程化配置
    │  ├── 合并 package.json (注入 devDependencies + scripts)
    │  ├── 渲染 Git hooks (commitlint / husky / lint-staged)
    │  └── 渲染 Git 基础文件 (.gitignore)
    │
10. [Git] 初始化 Git 仓库 + 首次提交
    │
11. 安装依赖 (pnpm install / flutter pub get)
    │
12. [husky] 初始化 Git hooks
    │
13. [shadcn/ui] 安装组件 + 格式化代码
    │
14. 触发 init:after 钩子
    │
15. 打印成功信息 + 工程化摘要 + 下一步提示
```

## 五、核心层：模板渲染引擎

这是整个脚手架的"心脏"。`src/core/template.ts` 中的 `generateProject()` 函数负责把模板变成最终项目。

### 渲染流程

```text
generateProject() 流程
═══════════════════════════════════════════════════

输入: { templateName, targetDir, projectName, answers, ... }
                    │
                    ▼
    ┌───────────────────────────────┐
    │ 1. 解析模板目录                 │
    │   本地: templates/{name}/     │
    │   远程: giget 下载到缓存        │
    └───────────────┬───────────────┘
                    │
                    ▼
    ┌───────────────────────────────┐
    │ 2. 构建 EJS 渲染上下文          │
    │   context = {                 │
    │     projectName,              │
    │     framework,                │
    │     uiLibrary,                │
    │     engineering,              │
    │     useTypeScript,            │
    │     year,                     │
    │     ...所有用户选择             │
    │   }                           │
    └───────────────┬───────────────┘
                    │
                    ▼
    ┌───────────────────────────────┐
    │ 3. 渲染业务模板                 │
    │   遍历 templates/{name}/ 下    │
    │   所有文件:                    │
    │   ├── .ejs 文件 → EJS 渲染     │
    │   │     替换 <%= projectName %>│
    │   │     替换 <%= framework %> │
    │   │     ...                   │
    │   ├── 非 .ejs 文件 → 直接复制   │
    │   └── 跳过不需要的文件          │
    │     (如没选 Tailwind → 跳过    │
    │      tailwind.config)         │
    └───────────────┬───────────────┘
                    │
                    ▼
    ┌───────────────────────────────┐
    │ 4. [Monorepo] 布局调整         │
    │   把应用移到 apps/web/          │
    │   共享代码放到 packages/shared/ │
    │   生成 turbo.json + workspace  │
    └───────────────┬───────────────┘
                    │
                    ▼
    ┌───────────────────────────────┐
    │ 5. 合并工程化配置               │
    │   从 engineering-base/ 目录    │
    │   选择性渲染:                   │
    │   ├── ESLint config (按框架)   │
    │   ├── Prettier config         │
    │   ├── Stylelint config        │
    │   ├── Vitest config           │
    │   ├── markdownlint / cspell   │
    │   └── Git hooks 文件          │
    │   然后合并 devDependencies     │
    │   和 scripts 到 package.json  │
    └───────────────┬───────────────┘
                    │
                    ▼
    ┌───────────────────────────────┐
    │ 6. 渲染 Git 基础文件            │
    │   .gitignore                  │
    └───────────────┬───────────────┘
                    │
                    ▼
输出: 项目文件已生成到 targetDir
      返回 EngineeringOptions (告诉调用方启用了哪些工具)
```

### EJS 模板示例

模板文件中用 `<%= %>` 包裹的变量会被替换：

```html
<!-- package.json.ejs (模板) -->
{
  "name": "<%= projectName %>",
  "version": "0.0.0",
  "scripts": {
    "dev": "vite"<% if (engineering.vitest) { %>,
    "test": "vitest run"<% } %>
  }
}

<!-- 渲染后变成 -->
{
  "name": "my-app",
  "version": "0.0.0",
  "scripts": {
    "dev": "vite",
    "test": "vitest run"
  }
}
```

### 文件过滤机制

不是所有模板文件都需要生成。`shouldSkipFile()` 和 `shouldSkipEngineeringFile()` 两个函数负责过滤：

```text
用户选择                      → 跳过的文件
─────────────────────────────────────────────────
cssFramework !== 'tailwindcss' → tailwind.config.*, postcss.config.*
cssFramework !== 'unocss'      → uno.config.*
uiLibrary !== 'shadcn-ui'      → components/ui/*, components.json
useTypeScript === false        → tsconfig.json, *.d.ts
mobilePlatform === 'flutter'   → *.tsx, *.vue, vite.config.*
```

## 七、核心层：钩子系统

基于 [hookable](https://github.com/unjs/hookable) 实现，允许插件在关键节点介入。

```text
init 命令生命周期中的钩子触发点:
═══════════════════════════════════════

  用户输入命令
       │
       ▼
  ┌─ init:before ──────────────────┐
  │  插件可以在这里:                │
  │  · 修改 answers                │
  │  · 创建额外文件                 │
  │  · 中断流程                    │
  └────────────────────────────────┘
       │
       ▼
  ┌─ init:prompts ─────────────────┐
  │  插件可以在这里修改用户答案      │
  └────────────────────────────────┘
       │
       ▼
  ┌─ template:before ──────────────┐
  │  插件可以在这里:                │
  │  · 替换模板目录                 │
  │  · 添加自定义模板文件            │
  └────────────────────────────────┘
       │
       ▼
  (模板渲染 + 工程化合并)
       │
       ▼
  ┌─ template:after ───────────────┐
  │  插件可以在这里:                │
  │  · 修改生成的文件               │
  │  · 追加配置                    │
  └────────────────────────────────┘
       │
       ▼
  (安装依赖 + Git 初始化)
       │
       ▼
  ┌─ init:after ───────────────────┐
  │  插件可以在这里:                │
  │  · 运行额外的命令               │
  │  · 发送通知                    │
  │  · 打印自定义提示               │
  └────────────────────────────────┘
       │
       ▼
  完成
```

### 插件示例

```ts
import { registerPlugin, hooks } from 'mirajay-cli'

// 注册一个插件，在项目创建后自动打开编辑器
registerPlugin({
  name: 'open-editor',
  setup(hooks) {
    hooks.hook('init:after', async (ctx) => {
      const { targetDir } = ctx
      // 在项目创建完成后执行 code 命令打开 VS Code
      await import('execa').then(({ execa }) =>
        execa('code', [targetDir])
      )
    })
  },
})
```

### 模板名称解析

`resolveTemplateName()` 函数根据用户的选择，决定使用哪个模板：

```text
用户选择                              → 模板名称
─────────────────────────────────────────────────────────────
desktop + vue                        → desktop-vue
desktop + react                      → desktop-react
mobile + h5 + vue                    → mobile-h5-vue
mobile + h5 + react                  → mobile-h5-react
mobile + taro                        → mobile-taro
mobile + uni-app                     → mobile-uni-app
mobile + react-native                → mobile-rn
mobile + flutter                     → mobile-flutter
micro-frontend + module-federation   → micro-module-federation-{react|vue}
  + same stack                         或 micro-module-federation-mixed-*
  + mixed stack
micro-frontend + wujie              → micro-wujie-{react|vue}
micro-frontend + micro-app          → micro-micro-app-{react|vue}
micro-frontend + qiankun            → micro-qiankun-{react|vue}
```

## 九、数据流：从用户输入到项目生成

```text
用户交互                    内部数据结构                    最终效果
═════════════════════════════════════════════════════════════════

? 项目类型: desktop    ─┐
? 框架: vue            ─┤
? UI库: element-plus   ─┤    ProjectAnswers {
? CSS: tailwindcss     ─┼──→   projectType: 'desktop',
? TypeScript: Yes      ─┤      framework: 'vue',
? Monorepo: Yes        ─┤      uiLibrary: 'element-plus',
? 工程化: standard     ─┤      cssFramework: 'tailwindcss',
? 包管理器: pnpm       ─┤      useTypeScript: true,
? Git: Yes             ─┤      useMonorepo: true,
                       │      engineering: { preset: 'standard', ... },
                       │      packageManager: 'pnpm',
                       │      initGit: true
                       │    }
                       │
                       │         │
                       │         │ resolveTemplateName(answers)
                       │         ▼
                       │    templateName = 'desktop-vue'
                       │
                       │         │
                       │         │ generateProject()
                       │         ▼
                       │    ┌────────────────────────────┐
                       │    │ templates/desktop-vue/     │ ← EJS 渲染
                       │    │   ├── package.json.ejs     │
                       │    │   ├── vite.config.ts.ejs   │
                       │    │   ├── src/main.ts.ejs      │
                       │    │   └── ...                  │
                       │    └────────────────────────────┘
                       │              +
                       │    ┌────────────────────────────┐
                       │    │ templates/monorepo-base/   │ ← Monorepo 布局
                       │    │   ├── turbo.json           │
                       │    │   ├── pnpm-workspace.yaml  │
                       │    │   └── packages/shared/     │
                       │    └────────────────────────────┘
                       │              +
                       │    ┌────────────────────────────┐
                       │    │ templates/engineering-base/│ ← 工程化配置
                       │    │   ├── eslint.vue.config.js │
                       │    │   ├── prettier.config.mjs  │
                       │    │   ├── vitest.config.vue.ts │
                       │    │   └── ...                  │
                       │    └────────────────────────────┘
                       │              +
                       │    ┌────────────────────────────┐
                       │    │ templates/git-base/        │ ← Git 基础
                       │    │   └── .gitignore.ejs       │
                       │    └────────────────────────────┘
                       │              │
                       │              ▼
                       │    最终生成的项目:
                       │    my-app/
                       │    ├── apps/web/          (业务代码)
                       │    │   ├── src/
                       │    │   ├── package.json   (ESLint / Stylelint / Vitest)
                       │    │   ├── eslint.config.js
                       │    │   ├── stylelint.config.mjs
                       │    │   ├── vitest.config.ts
                       │    │   └── ...
                       │    ├── packages/shared/   (共享包，不注入 lint)
                       │    ├── turbo.json
                       │    ├── pnpm-workspace.yaml
                       │    ├── prettier.config.mjs  (全仓共享)
                       │    ├── .editorconfig
                       │    ├── .gitignore
                       │    ├── .husky/             (Git hooks)
                       │    ├── commitlint.config.cjs
                       │    ├── lint-staged.config.mjs
                       │    └── package.json        (turbo + 共享工具 + hooks)
                       │
                       │    根工具如何被用到、包如何互引：
                       │    见 docs/05-模板系统详解.md「根目录资源如何被用到」
                       │
                       ▼
              pnpm install + git init + husky init
                       │
                       ▼
              项目就绪！
```
