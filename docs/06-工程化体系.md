# 工程化体系

> 本篇讲清楚：创建项目时勾选的「Minimal / Standard / Strict」到底做了什么，以及这些配置是怎么从 `engineering-base` 合并进你的新项目的。
>
> 想逐个工具（ESLint、Prettier、husky……）细看配置 → [06-工程化配置详解](./06-工程化配置详解.md)。

---

## 一、为什么要把工程化拆出来？

如果每个业务模板（`desktop-vue`、`mobile-taro`……）都各自复制一份 ESLint、Prettier、husky 配置：

- 改一条规则要改 20 个目录
- 不同模板规范容易漂移
- 新手模板里夹杂大量「看不懂但不敢删」的配置

所以 mirajay-cli 采用：

```text
业务模板         → 只负责「能跑起来的业务骨架」
engineering-base → 只负责「规范与质量工具」
创建时合并       → 按你选的预设，把需要的文件/依赖写进目标项目
```

---

## 二、三级预设一览

定义在 `src/core/engineering-manifest.ts` 的 `PRESET_DEFINITIONS`：

| 能力 | Minimal | Standard（推荐） | Strict |
|------|:-------:|:----------------:|:------:|
| ESLint | ✅ | ✅ | ✅ |
| Prettier | ✅ | ✅ | ✅ |
| Stylelint | ❌ | ✅ | ✅ |
| markdownlint | ❌ | ✅ | ✅ |
| cspell（拼写检查） | ❌ | ❌ | ✅ |
| Vitest | ❌ | ✅ | ✅ |
| commitlint | ❌ | ✅ | ✅ |
| husky | ❌ | ✅ | ✅ |
| lint-staged | ❌ | ✅ | ✅ |

还有第四档 **Custom**：在问答里逐项开关上述能力。

> 新手建议：直接选 **Standard**。既有代码规范、测试与提交规范，又不会一上来被拼写检查等工具淹没。

## 三、创建时发生了什么？

简化流程：

```text
用户选择预设（如 standard）
    │
    ▼
resolveEngineeringOptions()     ← 得到一份 EngineeringOptions 开关表
    │
    ▼
generateProject()
    │
    ├── 渲染业务模板（desktop-vue 等）
    ├── 如需 Monorepo：合并 monorepo-base
    ├── 按开关从 engineering-base 复制/渲染配置文件
    ├── 合并 package.json 的 scripts / devDependencies
    └── 如开启 husky：后续再 setupGitHooks()
```

关键文件：

| 文件 | 职责 |
|------|------|
| `src/core/engineering.ts` | 预设 → 开关表；摘要文案 |
| `src/core/engineering-manifest.ts` | 预设定义 + 要注入的依赖/脚本清单 |
| `src/core/engineering-profile.ts` | 按场景选 ESLint profile（react / vue / taro / uni-app / rn） |
| `templates/engineering-base/` | 真正的配置文件模板（大量 `.ejs`） |

---

## 四、engineering-base 里有什么？

大致包括（具体以仓库目录为准）：

- ESLint flat config（按框架分文件，如 `eslint.react.config.js.ejs`、`eslint.vue.config.js.ejs`）
- Prettier 相关忽略与配置
- Stylelint 配置（React / Vue 不同）
- Vitest smoke 测试样例
- markdownlint / cspell 配置
- commitlint + husky + lint-staged 相关文件

创建时**不会**把所有文件无脑拷贝过去，而是：

1. 看预设开关（比如没开 Stylelint 就跳过）
2. 看工程化 profile（Vue 项目不会拷 React 那份 ESLint）
3. 用 EJS 填入项目名、路径等变量
4. 把对应依赖版本合并进 `package.json`

## 五、和业务模板、Monorepo 的关系

```text
┌─────────────────┐
│  业务模板        │  apps 里的业务代码、路由、UI 接入
└────────┬────────┘
         │ 合并
┌────────▼────────┐
│ monorepo-base   │  （可选）根 workspace、turbo、shared 包
└────────┬────────┘
         │ 合并
┌────────▼────────┐
│ engineering-base│  规范与质量工具
└────────┬────────┘
         │ 合并
┌────────▼────────┐
│ git-base        │  .gitignore 等仓库级文件
└─────────────────┘
```

桌面 / H5 勾选 Monorepo 时：业务应用通常落在 `apps/web`，工程化配置会按 monorepo 布局注入到正确位置（见 `monorepo-engineering.ts`）。

## 六、生成项目后你怎么用？

在**生成出来的项目**里（不是脚手架仓库）：

```bash
pnpm lint      # ESLint（若启用）
pnpm format    # Prettier（若启用）
pnpm test      # Vitest（若启用）
pnpm commit    # 交互式规范提交（若启用 commitlint/cz）
```

提交代码时，若启用了 husky + lint-staged：

- `pre-commit`：对暂存文件跑 lint / format
- `commit-msg`：检查提交信息是否符合 Conventional Commits

## 七、小白常见困惑

**Q：为什么我的 Vue 项目没有 `eslint.react.config`？**  
A：正常。脚手架会按 profile 只留下适合当前栈的那一份。

**Q：我选了 Minimal，还能后来再加 husky 吗？**  
A：可以手动加，但脚手架不会「二次回填」。更省事的做法是创建时选 Standard / Strict，或 Custom 勾上需要的项。

**Q：工程化依赖版本在哪统一维护？**  
A：主要在 `engineering-manifest.ts`；维护者可用 `mirajay-cli update-deps` 批量同步模板与清单中的版本。
