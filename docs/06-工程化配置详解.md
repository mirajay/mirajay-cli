# 工程化配置详解

> 本篇详细讲解 mirajay-cli 内置的工程化工具：每个工具是什么、为什么需要、怎么配置的。

## 一、工程化工具全景

```text
┌────────────────────────────────────────────────────────────┐
│                    工程化工具体系                            │

│  代码质量     │  代码格式      │  测试        │  Git 规范      │
├──────────────┼──────────────┼──────────────┼───────────────┤
```

## 二、ESLint — 代码规范检查

### 是什么？

ESLint 是 JavaScript/TypeScript 的静态代码分析工具。它能在不运行代码的情况下，发现代码中的问题：

- 未使用的变量
- 未定义的变量
- 不安全的写法（如 `==` 应该用 `===`）
- React Hooks 使用错误
- Vue 模板语法问题

### 为什么需要？

```text
没有 ESLint:
  ├── 不同开发者代码风格不一
  ├── 低级错误带到生产环境
  └── Code Review 花大量时间挑格式问题

有 ESLint:
  ├── 统一代码规范
  ├── 编辑器实时提示错误
  └── CI 自动检查，不合规的代码无法合并
```

### 配置变体

mirajay-cli 为不同技术栈准备了 6 套 ESLint 配置：

| 变体 | 适用场景 | 特殊插件 |
|------|----------|----------|
| `eslint.react.config.js.ejs` | React 桌面/H5 | `eslint-plugin-react-hooks`, `eslint-plugin-react-refresh` |
| `eslint.vue.config.js.ejs` | Vue 桌面/H5 | `eslint-plugin-vue` |
| `eslint.taro.react.config.js.ejs` | Taro + React | Taro 专用规则 |
| `eslint.taro.vue.config.js.ejs` | Taro + Vue | Taro + Vue 规则 |
| `eslint.uni-app.config.js.ejs` | uni-app | uni-app 专用规则 |
| `eslint.react-native.config.js.ejs` | React Native | `eslint-plugin-react-native` |

### 依赖版本

React 项目 ESLint 依赖：

```json
{
  "eslint": "^9.21.0",
  "@eslint/js": "^9.21.0",
  "typescript-eslint": "^8.25.0",
  "eslint-plugin-react-hooks": "^5.2.0",
  "eslint-plugin-react-refresh": "^0.4.19",
  "globals": "^16.0.0"
}
```

Vue 项目 ESLint 依赖：

```json
{
  "eslint": "^9.21.0",
  "@eslint/js": "^9.21.0",
  "typescript-eslint": "^8.25.0",
  "eslint-plugin-vue": "^9.32.0",
  "globals": "^16.0.0"
}
```

> **注意**：如果用户选择不用 TypeScript（`useTypeScript: false`），会移除 `typescript-eslint` 依赖。

### 生成的 scripts

```json
{
  "scripts": {
    "lint:eslint": "eslint ."
  }
}
```

### ESLint 9 Flat Config

mirajay-cli 使用 ESLint 9 的 Flat Config 格式（`eslint.config.js`），而非旧的 `.eslintrc` 格式。Flat Config 更简洁，性能更好。

## 三、Prettier — 代码格式化

### 是什么？

Prettier 是"意见式"的代码格式化工具。它不管你的代码写得对不对，只管"好不好看"：

- 缩进用 2 空格还是 4 空格
- 字符串用单引号还是双引号
- 行尾要不要分号
- 换行规则

### 为什么需要？

```text
没有 Prettier:
  ├── 团队成员为"要不要分号"争论不休
  ├── Git diff 里全是格式改动，看不出真正改了什么
  └── 每个人手动调格式，浪费时间

有 Prettier:
  ├── 统一格式，无需争论
  ├── 保存文件时自动格式化
  └── Git diff 只显示真正的代码变更
```

### 配置文件

```js
// prettier.config.mjs
export default {
  semi: false,          // 不加分号
  singleQuote: true,    // 用单引号
  tabWidth: 2,          // 缩进 2 空格
  // ... 更多配置
}
```

### 依赖版本

```json
{
  "prettier": "^3.5.2"
}
```

### 生成的 scripts

```json
{
  "scripts": {
    "format": "prettier --write .",
    "format:check": "prettier --check ."
  }
}
```

### .prettierignore

```
dist/
node_modules/
*.min.js
pnpm-lock.yaml
```

## 四、Stylelint — 样式规范检查

### 是什么？

Stylelint 是 CSS/SCSS/Vue 样式的规范检查工具，类似 ESLint 但专门针对样式文件。

### 为什么需要？

- 检查 CSS 属性顺序
- 发现重复的样式规则
- 检测浏览器兼容性问题
- 统一样式书写规范

### 配置变体

| 变体 | 适用 | 额外依赖 |
|------|------|----------|
| `stylelint.react.config.mjs.ejs` | React 项目 | `stylelint-config-standard` |
| `stylelint.vue.config.mjs.ejs` | Vue 项目 | `stylelint-config-standard` + `stylelint-config-standard-vue` + `postcss-html` |

> Vue 项目需要额外检查 `.vue` 文件中的 `<style>` 块，所以需要 `stylelint-config-standard-vue` 和 `postcss-html`。

### 依赖版本

```json
// React
{
  "stylelint": "^16.14.1",
  "stylelint-config-standard": "^37.0.0"
}

// Vue
{
  "stylelint": "^16.14.1",
  "stylelint-config-standard": "^37.0.0",
  "stylelint-config-standard-vue": "^1.0.0",
  "postcss-html": "^1.7.0"
}
```

### 生成的 scripts

```json
{
  "scripts": {
    "lint:style": "stylelint \"**/*.{css,scss,vue}\" --allow-empty-input"
  }
}
```

### 默认启用条件

```ts
export function defaultStylelintForAnswers(answers: ProjectAnswers): boolean {
  if (answers.framework === 'vue') return true  // Vue 默认启用
  return answers.cssFramework === 'tailwindcss' || answers.cssFramework === 'unocss'
}
```

## 五、Vitest — 单元测试

### 是什么？

Vitest 是 Vite 原生的测试框架。语法和 Jest 兼容，但更快（利用 Vite 的转换管道）。

### 为什么需要？

```text
没有测试:
  ├── 改一行代码，不知道有没有破坏其他功能
  ├── 重构时提心吊胆
  └── Bug 反复出现

有测试:
  ├── 改代码后跑一遍测试，确认没有破坏
  ├── 重构时测试就是安全网
  └── 测试即文档，看测试就知道代码预期行为
```

### 配置变体

| 变体 | 适用 | 额外依赖 |
|------|------|----------|
| `vitest.config.react.ts.ejs` | React 项目 | `@vitejs/plugin-react`, `@testing-library/react`, `@testing-library/jest-dom`, `jsdom` |
| `vitest.config.vue.ts.ejs` | Vue 项目 | `@vue/test-utils`, `jsdom` |

### 测试文件

除了配置文件，还自动生成冒烟测试：

```text
src/__tests__/
├── setup.ts           ← 测试环境配置
└── smoke.test.ts      ← 冒烟测试（验证基础功能能跑通）
```

### 依赖版本

```json
// React
{
  "vitest": "^3.0.8",
  "@vitejs/plugin-react": "^4.3.4",
  "@testing-library/react": "^16.2.0",
  "@testing-library/jest-dom": "^6.6.3",
  "jsdom": "^26.0.0"
}

// Vue
{
  "vitest": "^3.0.8",
  "@vue/test-utils": "^2.4.6",
  "jsdom": "^26.0.0"
}
```

### 生成的 scripts

```json
{
  "scripts": {
    "test": "vitest run",
    "test:watch": "vitest"
  }
}
```

## 六、markdownlint — Markdown 规范

### 是什么？

markdownlint 检查 Markdown 文件的格式规范。

### 检查什么？

- 标题层级是否合理（不能从 H1 直接跳到 H3）
- 列表缩进是否一致
- 代码块是否标注语言
- 行尾空格
- 标题前后空行

### 配置文件

```json
// .markdownlint.json
{
  "default": true,
  "MD013": false,  // 不限制行长度
  "MD033": false   // 允许 HTML 标签
}
```

### 依赖版本

```json
{
  "markdownlint-cli": "^0.44.0"
}
```

### 生成的 scripts

```json
{
  "scripts": {
    "lint:md": "markdownlint \"**/*.md\""
  }
}
```

## 七、cspell — 拼写检查

### 是什么？

cspell 检查代码和文档中的拼写错误。

### 为什么需要？

- 变量名拼错（`recieve` → `receive`）
- 注释/文档中的拼写错误
- 避免因拼写错误导致的 Bug

### 配置文件

```json
// cspell.json
{
  "version": "0.2",
  "language": "en",
  "words": [],
  "ignorePaths": ["node_modules", "dist", "*.lock"]
}
```

### 依赖版本

```json
{
  "cspell": "^8.17.5"
}
```

### 生成的 scripts

```json
{
  "scripts": {
    "lint:spell": "cspell \"**/*.{ts,tsx,vue,md,json}\""
  }
}
```

> cspell 只在 Strict 预设中启用。

## 八、commitlint + cz-git — Git 提交规范

### 是什么？

- **commitlint**：检查 Git 提交信息是否符合规范
- **cz-git**：交互式提交工具，引导你写出规范的提交信息

### Conventional Commits 规范

```text
<type>(<scope>): <description>

[optional body]

[optional footer]
```

| Type | 说明 |
|------|------|
| `feat` | 新功能 |
| `fix` | 修复 Bug |
| `docs` | 文档变更 |
| `style` | 代码格式（不影响功能） |
| `refactor` | 重构 |
| `perf` | 性能优化 |
| `test` | 测试相关 |
| `chore` | 构建/工具变更 |

示例：

```
feat(auth): add OAuth2 login support

Allow users to log in using Google OAuth2.

Closes #123
```

### 为什么需要？

```text
没有提交规范:
  ├── 提交信息五花八门："fix bug"、"update"、"..."
  ├── 无法从提交历史中生成 Changelog
  └── 不知道某个提交是功能还是修复

有提交规范:
  ├── 提交信息清晰统一
  ├── 可以自动生成 Changelog
  └── 可以用脚本自动判断版本号怎么升
```

### 配置文件

```js
// commitlint.config.cjs
module.exports = {
  extends: ['@commitlint/config-conventional'],
}
```

### 依赖版本

```json
{
  "@commitlint/cli": "^19.8.0",
  "@commitlint/config-conventional": "^19.8.0",
  "cz-git": "^1.11.1"
}
```

### 生成的 scripts + config

```json
{
  "scripts": {
    "commit": "cz"
  },
  "config": {
    "commitizen": {
      "path": "node_modules/cz-git"
    }
  }
}
```

## 九、husky + lint-staged — Git Hooks

### husky 是什么？

husky 让你能在 Git 操作的特定时机自动执行脚本：

```text
git commit ──→ pre-commit 钩子 ──→ lint-staged ──→ 实际提交
          │
          └──→ commit-msg 钩子 ──→ commitlint 校验
```

### lint-staged 是什么？

lint-staged 只检查**暂存区**（`git add` 过的）文件，而不是全部文件。这样速度更快，不会因为其他文件的问题阻塞提交。

### 配置文件

```js
// .husky/pre-commit
npx lint-staged

// .husky/commit-msg
npx --no -- commitlint --edit "$1"
```

```js
// lint-staged.config.mjs
export default {
  '*.{ts,tsx,vue}': ['eslint --fix', 'prettier --write'],
  '*.{css,scss}': ['stylelint --fix', 'prettier --write'],
  '*.md': ['markdownlint --fix', 'prettier --write'],
}
```

### 依赖版本

```json
{
  "husky": "^9.1.7",
  "lint-staged": "^15.4.3"
}
```

### 生成的 scripts

```json
{
  "scripts": {
    "prepare": "husky"
  }
}
```

> `prepare` 脚本在 `pnpm install` 后自动执行，确保 husky 钩子被安装。

## 十、lint 命令的合成

当多个工具同时启用时，`lint` 脚本会自动合成：

```json
{
  "scripts": {
    "lint": "prettier --write . && eslint . && stylelint \"**/*.{css,scss,vue}\" --allow-empty-input && markdownlint \"**/*.md\""
  }
}
```

合成逻辑（在 `getEngineeringManifest()` 中）：

```ts
const lintParts: string[] = []

if (engineering.prettier) lintParts.unshift('prettier --write .')  // Prettier 放最前面
if (engineering.eslint) lintParts.push('eslint .')
if (engineering.stylelint) lintParts.push(`stylelint "${stylelintGlob}" --allow-empty-input`)
if (engineering.markdownlint) lintParts.push('markdownlint "**/*.md"')
if (engineering.spellcheck) lintParts.push(spellGlob)

if (lintParts.length > 0) {
  scripts.lint = lintParts.join(' && ')
}
```

> Prettier 用 `unshift` 放在最前面，这样先格式化再检查，避免格式问题被 ESLint 报错。

## 十一、EngineeringProfile — 配置档位

Profile 决定了用哪套 ESLint/Vitest/Stylelint 配置：

```text
用户选择                         → Profile          → ESLint 配置变体
────────────────────────────────────────────────────────────────────
desktop + react                 → 'react'          → eslint.react.config
desktop + vue                   → 'vue'            → eslint.vue.config
mobile + h5 + react             → 'react'          → eslint.react.config
mobile + h5 + vue               → 'vue'            → eslint.vue.config
mobile + taro + react           → 'taro-react'     → eslint.taro.react.config
mobile + taro + vue             → 'taro-vue'       → eslint.taro.vue.config
mobile + uni-app                → 'uni-app'        → eslint.uni-app.config
mobile + react-native           → 'react-native'   → eslint.react-native.config
mobile + flutter                → null             → 不注入 JS 工程化
```

## 十二、.editorconfig — 编辑器配置

```ini
# .editorconfig
root = true

[*]
charset = utf-8
end_of_line = lf
indent_style = space
indent_size = 2
insert_final_newline = true
trim_trailing_whitespace = true

[*.md]
trim_trailing_whitespace = false
```

> `.editorconfig` 让不同编辑器（VS Code、WebStorm、Sublime 等）统一基础格式。大多数编辑器内置支持或通过插件支持。
