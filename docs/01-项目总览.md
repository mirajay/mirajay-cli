## 一、背景：为什么需要脚手架？

### 没有脚手架的世界

假设你是一个新入职的前端开发者，接到任务要创建一个新的 Web 项目。你需要手动做这些事：

1. 新建文件夹，创建 `package.json`
2. 安装 Vite、React/Vue、TypeScript
3. 配置 Vite（别名、代理、插件）
4. 安装并配置 UI 组件库（Element Plus / Ant Design 等）
5. 安装并配置 CSS 框架（Tailwind CSS 等）
6. 配置 ESLint（代码规范检查）
7. 配置 Prettier（代码格式化）
8. 配置 Stylelint（样式规范检查）
9. 配置 Vitest（单元测试）
10. 配置 commitlint + husky（Git 提交规范）
11. 创建项目目录结构（src/、router/、views/ 等）
12. 配置 CI/CD 流水线
13. ...

**这个过程通常需要半天到一天**，而且不同人配置出来的结果不一致，容易出问题。

### 有脚手架的世界

```bash
mirajay-cli create my-app
# 回答几个问题 → 等1分钟 → 项目就配好了
```

**10 秒钟选择 + 1 分钟自动配置 = 开箱即用。**

## 二、mirajay-cli 能做什么？

### 核心能力

| 能力 | 说明 |
|------|------|
| **创建项目** | 交互式问答，自动生成完整前端项目 |
| **全端覆盖** | 桌面 Web、移动端（H5/Taro/uni-app/RN/Flutter）、微前端 |
| **多框架支持** | React 19 / Vue 3，十余种 UI 组件库 |
| **工程化内置** | ESLint、Prettier、Stylelint、Vitest、commitlint、husky 等 |
| **Monorepo** | 基于 Turborepo + pnpm workspace 的多包管理 |
| **模板引擎** | EJS 动态生成文件，按条件过滤不需要的文件 |
| **远程模板** | 通过 giget 从 GitHub/GitLab 拉取远程模板 |
| **插件体系** | 基于 hookable 的生命周期钩子，支持自定义扩展 |
| **命令工具** | lint、build、test、commit、doctor、deploy 等 |

### 支持的项目类型一览

## 三、技术栈一览

脚手架自身使用的技术：

| 技术 | 作用 | 通俗解释 |
|------|------|----------|
| **TypeScript** | 编程语言 | JavaScript 的增强版，有类型检查，写代码不容易出错 |
| **citty** | 命令行框架 | 帮你定义命令、解析参数、生成帮助信息 |
| **@inquirer/prompts** | 交互式问答 | 终端里的选择题、填空题组件 |
| **consola** | 日志工具 | 让终端输出更好看（带颜色、图标） |
| **picocolors** | 终端着色 | 给文字加颜色 |
| **c12** | 配置加载 | 读取 `.clirc.ts` 配置文件 |
| **giget** | 模板下载 | 从 GitHub 等远程仓库下载模板 |
| **hookable** | 钩子系统 | 在特定时机执行自定义代码（插件机制） |
| **EJS** | 模板引擎 | 把 `.ejs` 文件渲染成最终代码 |
| **execa** | 命令执行 | 在终端执行 `git init`、`pnpm install` 等命令 |
| **semver** | 版本比较 | 检查 Node.js 版本是否满足要求 |
| **tsup** | 打包工具 | 把 TypeScript 源码编译成可执行的 JS |
| **vitest** | 测试框架 | 跑单元测试，确保代码质量 |

## 五、一个请求的完整生命周期

当你输入 `mirajay-cli create my-app` 时，背后发生了什么？

```text
用户输入命令
    │
    ▼
bin/cli.mjs               ← 入口文件，加载 dist/index.js
    │
    ▼
src/index.ts              ← citty 注册的命令路由
    │
    ▼
src/commands/init.ts      ← 匹配到 create/init 命令
    │
    ├──→ src/core/config.ts       ← 加载 .clirc 配置
    │
    ├──→ src/core/prompts.ts      ← 启动交互式问答
    │       │
    │       └──→ @inquirer/prompts ← 渲染选择菜单
    │
    ├──→ src/core/hooks.ts        ← 触发 init:before 钩子
    │
    ├──→ src/core/template.ts     ← 核心：生成项目
    │       │
    │       ├──→ resolveTemplateName()    ← 根据答案选模板
    │       ├──→ renderTemplateDir()      ← EJS 渲染文件
    │       ├──→ engineering-base 合并    ← 注入工程化配置
    │       ├──→ monorepo-layout 布局     ← Monorepo 目录
    │       └──→ git-config / git-hooks   ← Git 配置
    │
    ├──→ src/core/utils.ts        ← 安装依赖 + 初始化 Git
    │
    ├──→ src/core/shadcn.ts       ← （如选了 shadcn/ui）安装组件
    │
    ├──→ src/core/hooks.ts        ← 触发 init:after 钩子
    │
    └──→ src/core/next-steps.ts   ← 打印"下一步"提示
    │
    ▼
项目创建完成，用户看到成功信息
```

## 六、设计理念

1. **约定优于配置**：提供合理的默认值（Standard 预设），新手不需要做太多选择
2. **渐进式复杂度**：从 Minimal → Standard → Strict → Custom，按需启用
3. **全端覆盖**：一套工具搞定桌面、移动、微前端，不用学多个脚手架
4. **模板与逻辑分离**：模板放在 `templates/` 目录（纯文件），逻辑放在 `src/` 目录（代码）
5. **可扩展**：通过 hookable 钩子系统，插件可以在关键节点注入自定义逻辑
6. **安全第一**：所有用户输入（框架名、UI 库名）经过白名单校验，防止注入攻击
