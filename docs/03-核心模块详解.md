## types.ts — 类型定义

**职责**：定义全局共享的 TypeScript 类型。

这个文件是整个项目的"契约"，所有模块都依赖这里定义的类型。

### 核心类型

#### ProjectAnswers — 用户的所有选择

```ts
export interface ProjectAnswers {
  projectType: 'desktop' | 'mobile' | 'micro-frontend'  // 项目类型
  framework?: 'react' | 'vue'                            // 前端框架
  uiLibrary?: string                                     // UI 组件库
  cssFramework?: 'tailwindcss' | 'unocss' | 'none'      // CSS 方案
  mobilePlatform?: 'h5' | 'taro' | 'uni-app' | 'react-native' | 'flutter'
  microFrontendTool?: 'module-federation' | 'wujie' | 'micro-app' | 'qiankun'
  microFrontendStackMode?: 'same' | 'mixed'              // MF 同栈/混合栈
  remoteFramework?: 'react' | 'vue'                      // MF 远程子应用框架
  useMonorepo?: boolean                                  // 是否用 Monorepo
  engineering?: EngineeringOptions                       // 工程化配置
  packageManager?: 'pnpm' | 'yarn' | 'bun' | 'npm'      // 包管理器
  initGit?: boolean                                      // 是否初始化 Git
  useTypeScript?: boolean                                // 是否用 TypeScript
  // Flutter 专属
  flutterStateManagement?: 'Provider' | 'Riverpod' | 'Bloc'
  flutterTargetPlatforms?: string[]
  flutterMaterial3?: boolean
  flutterInternationalization?: boolean
}
```

> **通俗理解**：就是一张"点菜单"。用户在交互式问答中的每个选择，都会填入这个对象。

#### EngineeringOptions — 工程化开关


#### 白名单常量


## core/logger.ts — 日志输出

**职责**：统一的终端输出风格。

```ts
import { createConsola } from 'consola'
import pc from 'picocolors'

export const logger = createConsola({ fancy: true })

export function success(message: string) {
  logger.success(pc.green(message))   // 绿色 + ✔ 图标
}

export function info(message: string) {
  logger.info(pc.cyan(message))       // 青色 + ℹ 图标
}

export function warn(message: string) {
  logger.warn(pc.yellow(message))     // 黄色 + ⚠ 图标
}

export function error(message: string) {
  logger.error(pc.red(message))       // 红色 + ✖ 图标
}

export function step(message: string) {
  logger.log(pc.bold(pc.blue('→'), message))  // 蓝色箭头
}

export function banner() {
  console.log(pc.bold(pc.cyan('  mirajay-cli')) + pc.dim(' - 企业级前端脚手架'))
  console.log(pc.dim('  桌面 Web · 移动端 · 微前端'))
}
```

> **为什么需要统一的 logger？**
> 直接 `console.log` 也可以输出，但没有颜色、没有图标，用户很难快速区分成功/警告/错误。统一 logger 让终端输出更专业、更易读。

## core/prompts.ts — 交互式问答

**职责**：通过终端交互收集用户的所有选择。

### 整体流程

```ts
export async function runInitPrompts(projectName?: string) {
  // 1. 项目名称
  const name = projectName || await input({ message: '项目名称', default: 'my-app' })

  // 2. 项目类型
  const projectType = await select({
    message: '选择项目类型',
    choices: [
      { name: '桌面 Web 应用', value: 'desktop' },
      { name: '移动端应用', value: 'mobile' },
      { name: '微前端架构', value: 'micro-frontend' },
    ],
  })

  // 3. 根据项目类型，动态决定后续问题
  const answers: ProjectAnswers = { projectType }

  if (projectType === 'mobile') {
    // 问移动端平台（H5 / Taro / uni-app / RN / Flutter）
    answers.mobilePlatform = await select({ ... })
  }

  if (projectType === 'micro-frontend') {
    // 问微前端方案（Module Federation / wujie / micro-app / qiankun）
    answers.microFrontendTool = await select({ ... })
    // 如果选了 Module Federation，还要问同栈还是混合栈
  }

  // 4. 框架选择（桌面/H5 需要选，uni-app 固定 Vue，Flutter 不需要）
  // 5. TypeScript 选择
  // 6. UI 组件库选择（根据框架动态展示不同选项）
  // 7. CSS 框架选择
  // 8. Monorepo 选择
  // 9. 工程化预设选择
  // 10. 包管理器选择
  // 11. Git 初始化选择

  return { projectName: name, answers }
}
```

## core/template.ts — 模板渲染引擎

**职责**：整个脚手架的核心，负责把模板文件渲染成最终项目。

这是最长、最复杂的文件。核心函数是 `generateProject()`。

### 关键函数

#### resolveTemplateName() — 根据用户选择确定模板名

```ts
export function resolveTemplateName(answers: ProjectAnswers): string {
  if (answers.projectType === 'desktop') {
    return answers.framework === 'vue' ? 'desktop-vue' : 'desktop-react'
  }
  if (answers.projectType === 'mobile') {
    switch (answers.mobilePlatform) {
      case 'h5': return answers.framework === 'vue' ? 'mobile-h5-vue' : 'mobile-h5-react'
      case 'taro': return 'mobile-taro'
      case 'uni-app': return 'mobile-uni-app'
      case 'react-native': return 'mobile-rn'
      case 'flutter': return 'mobile-flutter'
    }
  }
  if (answers.projectType === 'micro-frontend') {
    return resolveMicroFrontendTemplateName(answers.microFrontendTool!, answers)
  }
  return 'desktop-vue'
}
```

#### renderFile() — 渲染单个 EJS 文件

```ts
async function renderFile(sourcePath: string, targetPath: string, context: RenderContext) {
  const content = await readFile(sourcePath, 'utf-8')
  // 用 EJS 渲染：把 <%= projectName %> 替换成实际值
  const rendered = ejs.render(content, context, {
    escape: (value) => String(value),  // 禁用 HTML 转义
  })
  await mkdir(dirname(targetPath), { recursive: true })
  await writeFile(targetPath, rendered, 'utf-8')
}
```

> **为什么禁用 HTML 转义？** EJS 默认会把 `<` 转义成 `&lt;`，但我们生成的是代码文件（JS/JSON），不是 HTML，所以需要禁用转义，否则代码里的 `&&` 会变成 `&amp;&amp;`。

#### shouldSkipFile() — 文件过滤

```ts
function shouldSkipFile(relativePath: string, answers: ProjectAnswers): boolean {
  const filters = getFileFilters(answers)
  for (const filter of filters) {
    if (filter.match(relativePath)) {
      return filter.skip
    }
  }
  return false
}

function getFileFilters(answers: ProjectAnswers): FileFilter[] {
  const filters: FileFilter[] = []

  // 没选 Tailwind → 跳过 tailwind 相关文件
  if (answers.cssFramework !== 'tailwindcss') {
    filters.push({
      match: (p) => p.includes('tailwind') || p.includes('postcss.config'),
      skip: true,
    })
  }

  // 没选 UnoCSS → 跳过 uno.config
  if (answers.cssFramework !== 'unocss') {
    filters.push({ match: (p) => p.includes('uno.config'), skip: true })
  }

  // 没选 shadcn/ui → 跳过相关文件
  if (answers.uiLibrary !== 'shadcn-ui') {
    filters.push({
      match: (p) => p.includes('components/ui/') || p.includes('components.json'),
      skip: true,
    })
  }

  // 没用 TypeScript → 跳过 tsconfig
  if (!resolveUseTypeScript(answers) && answers.uiLibrary !== 'shadcn-ui') {
    filters.push({ match: (p) => isTypeScriptConfigPath(p), skip: true })
  }

  return filters
}
```

#### generateProject() — 主流程

```ts
export async function generateProject(options): Promise<EngineeringOptions> {
  // 1. 解析模板目录（本地 or 远程）
  const { templateDir, localTemplatesDir } = await resolveTemplateDirectory(options)

  // 2. 解析工程化选项
  const engineering = resolveEngineeringOptions(answers)

  // 3. 构建 EJS 渲染上下文
  const context: RenderContext = {
    ...answers,
    projectName,
    year: new Date().getFullYear(),
    engineering,
    useTypeScript: resolveUseTypeScript(answers),
    // ... 其他上下文
  }

  // 4. 渲染业务模板
  await renderTemplateDir(templateDir, appTargetDir, context, answers)

  // 5. [Monorepo] 生成 Monorepo 布局
  if (shouldUseMonorepoLayout(answers, templateName)) {
    await finalizeMonorepoLayout({ ... })
  }

  // 6. 合并工程化配置
  if (hasAnyEngineering(engineering) && supportsEngineeringBase(answers)) {
    // 从 engineering-base/ 目录渲染 ESLint / Prettier / Vitest 等配置
    await renderTemplateDir(engineeringDir, appTargetDir, context, answers, {
      engineeringMode: true,
      engineering,
    })

    // 合并 devDependencies 和 scripts 到 package.json
    const manifest = getEngineeringManifest({ profile, engineering, ... })
    await mergePackageManifest(appTargetDir, manifest)

    // [Monorepo] 向子包注入工程化
    await mergeEngineeringToWorkspacePackages({ ... })

    // 渲染 Git hooks 文件
    await renderGitHooksFiles({ ... })
  }

  // 7. 渲染 Git 基础文件
  await renderGitBaseFiles({ ... })

  return engineering
}
```

### ENGINEERING_OUTPUT_MAP — 文件名映射

有些工程化模板文件有多个变体（React 版、Vue 版），渲染时需要映射成统一的输出文件名：

```ts
const ENGINEERING_OUTPUT_MAP: Record<string, string> = {
  'eslint.react.config.js.ejs': 'eslint.config.js',      // React ESLint → eslint.config.js
  'eslint.vue.config.js.ejs': 'eslint.config.js',        // Vue ESLint → 同样输出为 eslint.config.js
  'vitest.config.react.ts.ejs': 'vitest.config.ts',      // React Vitest → vitest.config.ts
  'vitest.config.vue.ts.ejs': 'vitest.config.ts',        // Vue Vitest → 同样
  // ...
}
```

> **设计思路**：模板中有 `eslint.react.config.js.ejs` 和 `eslint.vue.config.js.ejs` 两个文件，但最终输出都叫 `eslint.config.js`。渲染时根据 Profile 只选其中一个，另一个被 `shouldSkipEngineeringFile()` 跳过。

## core/hooks.ts — 插件钩子系统

**职责**：定义生命周期钩子，支持插件扩展。

```ts
import { createHooks } from 'hookable'

// 定义所有可用的钩子
export interface CliHooks {
  'init:before': (ctx: InitContext) => void | Promise<void>
  'init:after': (ctx: InitContext) => void | Promise<void>
  'init:prompts': (answers: Partial<ProjectAnswers>) => void | Promise<void>
  'template:before': (ctx: TemplateContext) => void | Promise<void>
  'template:after': (ctx: TemplateContext) => void | Promise<void>
  'lint:before': () => void | Promise<void>
  'lint:after': () => void | Promise<void>
  'build:before': () => void | Promise<void>
  'build:after': () => void | Promise<void>
}

// 创建钩子实例
export const hooks = createHooks<CliHooks>()

// 插件注册函数
export function registerPlugin(plugin: {
  name: string
  setup?: (hooks: typeof hooks) => void | Promise<void>
}) {
  return plugin
}
```

> **什么是 hookable？**
> 它是 unjs 生态的一个极简事件系统。你可以 `hooks.hook('事件名', 回调函数)` 注册监听器，然后 `hooks.callHook('事件名', 数据)` 触发所有监听器。类似于浏览器里的 `addEventListener`。

## core/config.ts — 配置加载

**职责**：加载 `.clirc` 配置文件，允许用户自定义脚手架默认行为。

```ts
import { loadConfig } from 'c12'

const DEFAULT_CONFIG: CliConfig = {
  defaultPackageManager: 'pnpm',
  defaultEngineeringPreset: 'standard',
}

export async function loadCliConfig(cwd: string = process.cwd()): Promise<CliConfig> {
  const { config } = await loadConfig<CliConfig>({

    cwd,
```

## core/engineering.ts — 工程化预设

**职责**：管理工程化预设（Minimal / Standard / Strict / Custom）。

```ts
// 根据用户选择解析出最终的工程化选项
export function resolveEngineeringOptions(answers: ProjectAnswers): EngineeringOptions {
  if (answers.engineering) {
    const { preset } = answers.engineering
    if (preset !== 'custom') {
      // 非 custom 预设，从预定义的配置中取值
      return { preset, ...PRESET_DEFINITIONS[preset] }
    }
    return answers.engineering  // custom 预设直接返回用户选择
  }
  // 默认用 Standard
  return { ...DEFAULT_ENGINEERING_STANDARD }
}

// 判断是否启用了任何工程化工具
export function hasAnyEngineering(options: EngineeringOptions): boolean {
  return options.eslint || options.prettier || options.stylelint || ...
}

// 格式化工程化摘要（用于终端展示）
export function formatEngineeringSummary(options: EngineeringOptions): string[] {
  const items: string[] = []
  if (options.eslint) items.push('ESLint')
  if (options.prettier) items.push('Prettier')
  if (options.stylelint) items.push('Stylelint')
  // ...
  return items
}
```

### 关键设计：init 时自动补全 Git hooks

```ts
// 如果用户选了 Minimal 预设 + 初始化 Git
// 自动补上 commitlint + husky + lint-staged
export function applyGitHooksForInitGit(answers: ProjectAnswers): void {
  if (!answers.initGit || !answers.engineering) return
  if (answers.engineering.preset === 'minimal') {
    answers.engineering = {
      ...answers.engineering,
      commitlint: true,
      husky: true,
      lintStaged: true,
    }
  }
}
```

> **为什么这样做？** Minimal 预设本身不含 Git hooks，但如果用户要初始化 Git 仓库，没有提交规范容易出问题。所以在 init 时自动补上，保证"有 Git 就有提交规范"。

```ts
}

const ESLINT_VUE_DEPS = {
  eslint: '^9.21.0',
  '@eslint/js': '^9.21.0',
  'typescript-eslint': '^8.25.0',
  'eslint-plugin-vue': '^9.32.0',
  globals: '^16.0.0',
}

// 根据 Profile 选择对应的依赖
function getEslintDeps(profile: EngineeringProfile) {
  switch (profile) {
    case 'vue': return ESLINT_VUE_DEPS
    case 'react-native': return ESLINT_REACT_NATIVE_DEPS
    case 'taro-vue':
    case 'uni-app': return ESLINT_VUE_DEPS
    default: return ESLINT_REACT_DEPS
  }
}

// 最终计算函数
export function getEngineeringManifest(options): PackageManifestPatch {
  const devDependencies: Record<string, string> = {}
  const scripts: Record<string, string> = {}

  if (engineering.eslint) {
    Object.assign(devDependencies, getEslintDeps(profile))
    scripts['lint:eslint'] = 'eslint .'
  }
  if (engineering.prettier) {
    Object.assign(devDependencies, PRETTIER_DEPS)
    scripts['format'] = 'prettier --write .'
  }
  if (engineering.vitest) {
    Object.assign(devDependencies, getVitestDeps(profile))
    scripts.test = 'vitest run'
  }
  // ... 其他工具

  return { devDependencies, scripts }
}
```

> **设计思路**：把"哪些预设启用哪些工具"和"每个工具需要什么依赖"分开管理。预设定义在 `engineering-manifest.ts` 顶部（数据），依赖选择逻辑在函数中（行为），清晰分离。

## core/engineering-profile.ts — 配置档位

**职责**：根据用户选择，确定工程化配置的"档位"（React / Vue / Taro / uni-app / RN）。

```ts
export type EngineeringProfile =
  | 'react' | 'vue' | 'taro-react' | 'taro-vue' | 'uni-app' | 'react-native'

export function resolveEngineeringProfile(answers: ProjectAnswers): EngineeringProfile | null {
  if (answers.mobilePlatform === 'flutter') return null  // Flutter 不走 JS 工程化

  if (answers.mobilePlatform === 'taro') {
    return answers.framework === 'vue' ? 'taro-vue' : 'taro-react'
  }
  if (answers.mobilePlatform === 'uni-app') return 'uni-app'
  if (answers.mobilePlatform === 'react-native') return 'react-native'

  if (answers.framework === 'vue') return 'vue'
  if (answers.framework === 'react') return 'react'

  return null
}

// 辅助函数
export function profileUsesReact(profile) {
  return profile === 'react' || profile === 'taro-react' || profile === 'react-native'
}
export function profileUsesVue(profile) {
  return profile === 'vue' || profile === 'taro-vue' || profile === 'uni-app'
}
```

> **为什么需要 Profile？**
> 同样是 ESLint，React 项目和 Vue 项目用的插件不同（React 需要 `eslint-plugin-react-hooks`，Vue 需要 `eslint-plugin-vue`）。Profile 就是告诉系统"该用哪套配置"。

## core/merge-package.ts — 合并 package.json

**职责**：把工程化依赖合并到生成的项目的 `package.json` 中。

```ts
export async function mergePackageManifest(
  targetDir: string,
  patch: PackageManifestPatch,
): Promise<void> {
  const pkgPath = join(targetDir, 'package.json')
  const raw = await readFile(pkgPath, 'utf-8')
  const pkg = JSON.parse(raw)

  // 合并 devDependencies（后面的覆盖前面的）
  pkg.devDependencies = {
    ...pkg.devDependencies,
    ...patch.devDependencies,
  }

  // 合并 scripts
  pkg.scripts = {
    ...pkg.scripts,
    ...patch.scripts,
  }

  // 合并 config（commitizen 配置等）
  if (patch.config) {
    pkg.config = { ...(pkg.config || {}), ...patch.config }
  }

  await writeFile(pkgPath, `${JSON.stringify(pkg, null, 2)}\n`, 'utf-8')
}
```

> **通俗理解**：模板里已经有一个基础的 `package.json`（包含 Vue/Vite 等依赖），工程化系统算出需要额外加的依赖（ESLint/Prettier 等），这个函数把两者合并到一起。

```ts
export async function installDependencies(targetDir, packageManager = 'pnpm') {
```

```ts
  await execa('git', ['config', 'user.email', 'mirajay-cli@local'], { cwd: targetDir })
  // 添加所有文件并提交
  await execa('git', ['add', '.'], { cwd: targetDir })
  await execa('git', ['commit', '-m', 'chore: initial commit from mirajay-cli'], { cwd: targetDir })
}
```

### detectProjectType() — 检测项目类型

```ts
export async function detectProjectType(cwd: string): Promise<string | null> {
  const checks = [
    { file: 'pubspec.yaml', type: 'flutter' },       // Flutter
    { file: 'turbo.json', type: 'monorepo' },        // Monorepo
    { file: 'vite.config.ts', type: 'vite' },        // Vite 项目
    { file: 'vite.config.js', type: 'vite' },
  ]
  for (const check of checks) {
    try {
      await access(join(cwd, check.file))
      return check.type
    } catch { /* 继续检查下一个 */ }
  }
  return null
}
```

> **用途**：`build` 和 `lint` 命令用这个函数判断当前项目的类型，然后调用对应的构建/检查工具。

## core/remote-templates.ts — 远程模板

**职责**：通过 giget 从 GitHub/GitLab 等远程仓库下载模板。

```ts
import { downloadTemplate } from 'giget'

// 判断是否是远程模板源
export function isRemoteTemplateSource(source: string): boolean {
  return /^(gh:|gitlab:|bitbucket:|git:|https?:\/\/|file:\/\/)/.test(source.trim())
}

// 安全校验
export function validateRemoteTemplateSource(source: string): void {
  if (!REMOTE_SOURCE_PATTERN.test(source.trim())) {
    throw new Error(`Invalid remote template source: ${source}`)
  }
  // 防止命令注入
  if (/[;&|`$]/.test(source.trim())) {
    throw new Error('Remote template source contains invalid characters')
  }
}

// 下载远程模板
export async function fetchRemoteTemplate(source: string, options?) {
  const dir = getCacheDir(source, options?.cacheDir)  // 带缓存的目录
  step(`下载远程模板: ${source}`)
  const result = await downloadTemplate(source.trim(), { dir, force: options?.force })
  return result.dir
}
```

### 使用方式


## core/templates-dir.ts — 模板目录定位

**职责**：找到 `templates/` 目录的位置。

```ts
function resolveDefaultTemplatesDir(): string {
  const moduleDir = dirname(fileURLToPath(import.meta.url))
  // 开发时：dist/ 和 templates/ 在同一层级
  // 发布后：可能在不同层级
  const candidates = [
    join(moduleDir, '../templates'),
    join(moduleDir, '../../templates'),
  ]
  for (const dir of candidates) {
    if (existsSync(dir)) return dir
  }
  throw new Error('Templates directory not found.')
}

export function getTemplatesDir(customDir?: string): string {
  if (!customDir) return DEFAULT_TEMPLATES_DIR
  return isAbsolute(customDir) ? customDir : resolve(process.cwd(), customDir)
}
```

> **为什么需要候选路径？** 开发时 `dist/index.js` 和 `templates/` 在同一层级（`../templates`）。但 npm 安装后，包结构可能不同，所以需要两个候选路径。

## core/typescript-mode.ts — TS/JS 模式

**职责**：管理 TypeScript / JavaScript 模式的切换。

```ts
// 是否展示 TypeScript 选项给用户
export function supportsTypeScriptChoice(answers: ProjectAnswers): boolean {
  // 这些平台固定使用 TS，不需要问用户
  if (answers.mobilePlatform === 'flutter') return false
  if (answers.mobilePlatform === 'taro') return false

  return true  // 桌面和 H5 可以选

  if (!supportsTypeScriptChoice(answers)) return true  // 固定 TS 的平台
  return answers.useTypeScript !== false  // 默认 true

// JS 模式下把 .ts → .js, .tsx → .jsx
export function applyJavaScriptExtension(path: string, useTypeScript: boolean): string {
  if (useTypeScript) return path
  if (path.endsWith('.tsx')) return `${path.slice(0, -4)}.jsx`
  if (path.endsWith('.ts')) return `${path.slice(0, -3)}.js`
  return path
}
```

## core/monorepo-layout.ts — Monorepo 布局

**职责**：当用户选择 Monorepo 时，调整项目目录结构。

```ts
// 是否使用 Monorepo 布局（微前端模板自带 Monorepo，不额外处理）
export function shouldUseMonorepoLayout(answers, templateName): boolean {
  return Boolean(answers.useMonorepo) && !templateName.startsWith('micro-')
}

// 应用代码放在 apps/web/ 下
export function resolveAppTargetDir(targetDir, answers, templateName): string {
  if (shouldUseMonorepoLayout(answers, templateName)) {
    return join(targetDir, 'apps/web')
  }
  return targetDir
}

// 生成 Monorepo 根目录结构
export async function finalizeMonorepoLayout(options) {
  // 1. 从 monorepo-base/ 模板渲染根目录文件（turbo.json, pnpm-workspace.yaml 等）
  await renderTemplateDir(monorepoDir, rootDir, context, answers)

  // 2. 生成 packages/shared/ 共享包
  await renderTemplateDir(sharedDir, join(rootDir, 'packages/shared'), context, answers)

  // 3. 创建 apps/ 和 packages/ 目录
  await mkdir(join(rootDir, 'apps'), { recursive: true })
  await mkdir(join(rootDir, 'packages'), { recursive: true })
}
```

```text
│       ├── src/

│       └── vite.config.ts
├── packages/
│   └── shared/              ← 共享包
│       ├── src/
│       └── package.json
├── turbo.json               ← Turborepo 配置
├── pnpm-workspace.yaml      ← pnpm 工作区
```

## core/git-hooks.ts — Git Hooks

**职责**：生成 commitlint、husky、lint-staged 配置文件。

```ts
// 需要渲染的 Git hooks 文件映射
const GIT_HOOKS_FILES = {
  'git-hooks/commitlint.config.cjs.ejs': 'commitlint.config.cjs',
  'git-hooks/lint-staged.config.mjs.ejs': 'lint-staged.config.mjs',
  'git-hooks/husky/pre-commit.ejs': '.husky/pre-commit',
  'git-hooks/husky/commit-msg.ejs': '.husky/commit-msg',
}

export async function renderGitHooksFiles(options) {
  if (!shouldRenderGitHooks(engineering)) return

  for (const [sourceRel, targetRel] of Object.entries(GIT_HOOKS_FILES)) {
    // 按需跳过未启用的工具
    if (targetRel.includes('husky/pre-commit') && (!engineering.husky || !engineering.lintStaged)) continue
    if (targetRel.includes('husky/commit-msg') && (!engineering.husky || !engineering.commitlint)) continue
    if (targetRel.includes('lint-staged') && !engineering.lintStaged) continue
    if (targetRel.includes('commitlint.config') && !engineering.commitlint) continue

    // 渲染 EJS 文件
    const content = await readFile(sourcePath, 'utf-8')
    const rendered = ejs.render(content, context)
    await writeFile(targetPath, rendered)
  }
}
```

### 这些文件分别是干什么的？

| 文件 | 作用 |
|------|------|
| `commitlint.config.cjs` | 定义 Git 提交信息规范（如 `feat: xxx`） |
| `lint-staged.config.mjs` | 定义 `git commit` 时只检查暂存文件的规则 |
| `.husky/pre-commit` | Git commit 前自动执行 lint-staged |
| `.husky/commit-msg` | Git commit 时校验提交信息格式 |
