# 开发指南

> 本篇面向想参与 mirajay-cli 开发的开发者，讲解如何搭建开发环境、添加新命令、添加新模板、编写测试。

---

## 一、开发环境搭建

### 前置要求

- Node.js >= 24.18.0
- pnpm（推荐）
- Git

### 搭建步骤

```bash
# 1. 克隆仓库
git clone <repo-url>
cd mirajay-cli

# 2. 安装依赖
pnpm install

# 3. 启动监听模式（修改代码自动重新编译）
pnpm dev

# 4. 全局链接（这样你可以在任何地方用 mirajay-cli 命令）
pnpm link --global
```

### 开发工作流

```text
修改 src/ 下的代码
    │
    ├── pnpm dev 在监听模式会自动重新编译
    │   → dist/index.js 更新
    │
    └── 在终端测试
        mirajay-cli create test-app
```

### 常用脚本

| 命令 | 说明 |
|------|------|
| `pnpm dev` | 监听模式构建（修改代码自动编译） |
| `pnpm build` | 一次性构建 |
| `pnpm test` | 运行所有测试 |
| `pnpm test:watch` | 监听模式运行测试 |
| `pnpm lint` | ESLint 检查 |
| `pnpm typecheck` | TypeScript 类型检查 |

## 二、项目构建配置

### tsup.config.ts

```ts
import { defineConfig } from 'tsup'

export default defineConfig({
  entry: ['src/index.ts'],  // 入口文件
  format: ['esm'],          // 只输出 ESM 格式
  dts: true,                // 生成类型声明文件
  clean: true,              // 构建前清空 dist/
  sourcemap: true,          // 生成 sourcemap
  target: 'node24',         // 目标 Node.js 24
  splitting: false,         // 不做代码分割
  shims: false,             // 不注入 process 等 polyfill
})
```

> **为什么用 tsup？** tsup 基于 esbuild，构建速度极快。它把 TypeScript 编译成 JavaScript，同时生成类型声明文件（.d.ts）和 sourcemap。

### tsconfig.json 关键配置

```json
{
  "compilerOptions": {
    "target": "ESNext",           // 编译目标
    "module": "ESNext",           // 模块格式
    "moduleResolution": "bundler", // 模块解析策略
    "strict": true,               // 严格模式
    "declaration": true,          // 生成 .d.ts
    "outDir": "dist",             // 输出目录
    "rootDir": "src",             // 源码目录
    "noUnusedLocals": true,       // 禁止未使用的局部变量
    "noUnusedParameters": true    // 禁止未使用的参数
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist", "templates"]
}
```

### vitest.config.ts

```ts
import { defineConfig } from 'vitest/config'

export default defineConfig({
  test: {
    globals: false,            // 不注入全局变量
    environment: 'node',       // Node.js 环境
    include: ['tests/**/*.test.ts'],
  },
})
```

## 三、添加新命令

### 步骤 1：创建命令文件

在 `src/commands/` 下创建新文件，例如 `clean.ts`：

```ts
// src/commands/clean.ts
import { defineCommand } from 'citty'
import { execa } from 'execa'
import { banner, step, success, warn } from '../core/logger.js'
import { hooks } from '../core/hooks.js'

export default defineCommand({
  meta: {
    name: 'clean',
    description: '清理构建产物和缓存',
  },
  args: {
    all: {
      type: 'boolean',
      description: '同时清理 node_modules',
      alias: 'a',
      default: false,
    },
  },
  async run({ args }) {
    banner()
    step('清理构建产物...')

    await hooks.callHook('clean:before')

    // 删除 dist/ 目录
    try {
      await execa('rm', ['-rf', 'dist'], { stdio: 'pipe' })
      success('已清理 dist/')
    } catch {
      warn('dist/ 目录不存在')
    }

    if (args.all) {
      step('清理 node_modules...')
      await execa('rm', ['-rf', 'node_modules'], { stdio: 'pipe' })
      success('已清理 node_modules/')
    }

    await hooks.callHook('clean:after')
    success('清理完成')
  },
})
```

### 步骤 2：注册命令

在 `src/index.ts` 中注册：

```ts
import clean from './commands/clean.js'

const main = defineCommand({
  // ...
  subCommands: {
    // ... 已有命令
    clean,  // 添加新命令
  },
})
```

### 步骤 3：添加钩子（可选）

如果需要支持插件扩展，在 `src/core/hooks.ts` 中添加钩子：

```ts
export interface CliHooks {
  // ... 已有钩子
  'clean:before': () => void | Promise<void>
  'clean:after': () => void | Promise<void>
}
```

### 步骤 4：编写测试

在 `tests/` 下创建测试文件：

```ts
// tests/clean.test.ts
import { describe, it, expect } from 'vitest'

describe('clean command', () => {
  it('should be defined', async () => {
    const mod = await import('../src/commands/clean.js')
    expect(mod.default).toBeDefined()
  })
})
```

### 步骤 5：测试

```bash
pnpm build
mirajay-cli clean --help    # 查看帮助
mirajay-cli clean            # 运行
mirajay-cli clean -a         # 带 --all 参数
```

## 四、添加新模板

### 步骤 1：确定模板需求

假设要添加一个 "Svelte 桌面应用" 模板。

### 步骤 2：创建模板目录

```bash
mkdir -p templates/desktop-svelte/src
```

### 步骤 3：编写模板文件

```text
templates/desktop-svelte/
├── package.json.ejs
├── vite.config.ts.ejs
├── index.html.ejs
├── tsconfig.json
├── svelte.config.js
└── src/
    ├── main.ts.ejs
    ├── App.svelte.ejs
    └── app.css
```

`package.json.ejs` 示例：

```json
{
  "name": "<%= projectName %>",
  "version": "0.0.0",
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"<% if (engineering.eslint) { %>,
    "lint": "eslint ."<% } %>
  },
  "dependencies": {
    "svelte": "^5.0.0"
  },
  "devDependencies": {
    "@sveltejs/vite-plugin-svelte": "^4.0.0",
    "svelte-check": "^4.0.0"
  }
}
```

### 步骤 4：注册模板名解析

在 `src/core/template.ts` 的 `resolveTemplateName()` 中：

```ts
export function resolveTemplateName(answers: ProjectAnswers): string {
  if (answers.projectType === 'desktop') {
    if (answers.framework === 'vue') return 'desktop-vue'
    if (answers.framework === 'react') return 'desktop-react'
    if (answers.framework === 'svelte') return 'desktop-svelte'  // 新增
  }
  // ...
}
```

### 步骤 5：添加交互选项

在 `src/core/prompts.ts` 中添加 Svelte 选项：

```ts
answers.framework = await select({
  message: '选择前端框架',
  choices: [
    { name: 'React', value: 'react' },
    { name: 'Vue', value: 'vue' },
    { name: 'Svelte', value: 'svelte' },  // 新增
  ],
})
```

### 步骤 6：更新类型和白名单

在 `src/types.ts` 中：

```ts
export interface ProjectAnswers {
  framework?: 'react' | 'vue' | 'svelte'  // 添加 svelte
  // ...
}

export const ALLOWED_FRAMEWORKS = new Set(['react', 'vue', 'svelte'])
```

### 步骤 7：更新 EngineeringProfile（如果需要）

如果 Svelte 需要不同的 ESLint 配置，在 `src/core/engineering-profile.ts` 中添加：

```ts
export type EngineeringProfile =
  | 'react' | 'vue' | 'svelte' | 'taro-react' | ...

export function resolveEngineeringProfile(answers: ProjectAnswers) {
  // ...
  if (answers.framework === 'svelte') return 'svelte'
  // ...
}
```

然后在 `engineering-manifest.ts` 中添加 Svelte 的 ESLint 依赖。

### 步骤 8：编写测试

```ts
// tests/svelte.test.ts
import { describe, it, expect } from 'vitest'
import { resolveTemplateName } from '../src/core/template.js'

describe('Svelte template', () => {
  it('should resolve desktop-svelte', () => {
    const answers = { projectType: 'desktop', framework: 'svelte' }
    expect(resolveTemplateName(answers as any)).toBe('desktop-svelte')
  })
})
```

### 步骤 9：测试

```bash
pnpm build
mirajay-cli create test-svelte
# 选择 Svelte，验证生成的项目
cd test-svelte
pnpm install
pnpm dev
```

## 五、编写测试

### 测试文件组织

```text
tests/
├── *.test.ts              ← 单元测试
└── helpers/               ← 测试辅助函数
```

### 测试示例

#### 测试模板名解析

```ts
import { describe, it, expect } from 'vitest'
import { resolveTemplateName } from '../src/core/template.js'

describe('resolveTemplateName', () => {
  it('desktop + vue → desktop-vue', () => {
    expect(resolveTemplateName({ projectType: 'desktop', framework: 'vue' }))
      .toBe('desktop-vue')
  })

  it('mobile + flutter → mobile-flutter', () => {
    expect(resolveTemplateName({ projectType: 'mobile', mobilePlatform: 'flutter' }))
      .toBe('mobile-flutter')
  })

  it('micro-frontend + module-federation + react → micro-module-federation-react', () => {
    expect(resolveTemplateName({
      projectType: 'micro-frontend',
      microFrontendTool: 'module-federation',
      framework: 'react',
      microFrontendStackMode: 'same',
    })).toBe('micro-module-federation-react')
  })
})
```

#### 测试工程化预设

```ts
import { describe, it, expect } from 'vitest'
import { createEngineeringFromPreset, hasAnyEngineering } from '../src/core/engineering.js'

describe('engineering presets', () => {
  it('minimal preset should have eslint and prettier only', () => {
    const opts = createEngineeringFromPreset('minimal')
    expect(opts.eslint).toBe(true)
    expect(opts.prettier).toBe(true)
    expect(opts.stylelint).toBe(false)
    expect(opts.vitest).toBe(false)
  })

  it('standard preset should have all core tools', () => {
    const opts = createEngineeringFromPreset('standard')
    expect(opts.eslint).toBe(true)
    expect(opts.prettier).toBe(true)
    expect(opts.stylelint).toBe(true)
    expect(opts.vitest).toBe(true)
    expect(opts.commitlint).toBe(true)
    expect(opts.husky).toBe(true)
  })
})
```

#### 测试 EJS 渲染

```ts
import { describe, it, expect } from 'vitest'
import ejs from 'ejs'

describe('EJS rendering', () => {
  it('should render projectName', () => {
    const template = '{"name": "<%= projectName %>"}'
    const result = ejs.render(template, { projectName: 'my-app' })
    expect(JSON.parse(result).name).toBe('my-app')
  })

  it('should conditionally include content', () => {
    const template = '{"scripts": {"dev": "vite"<% if (hasTest) { %>, "test": "vitest"<% } %>}}'
    const withTest = ejs.render(template, { hasTest: true })
    const withoutTest = ejs.render(template, { hasTest: false })
    expect(JSON.parse(withTest).scripts.test).toBe('vitest')
    expect(JSON.parse(withoutTest).scripts.test).toBeUndefined()
  })
})
```

### 运行测试

```bash
# 运行所有测试
pnpm test

# 监听模式（修改代码自动重跑）
pnpm test:watch

# 运行特定测试文件
npx vitest run tests/template.test.ts
```

## 六、提交规范

### Conventional Commits

```bash
# 使用脚手架自带的 commit 命令（交互式）
mirajay-cli commit

# 或手动提交
git add .
git commit -m "feat(auth): add OAuth2 login support"
```

### 提交类型

| Type | 说明 | 示例 |
|------|------|------|
| `feat` | 新功能 | `feat: add Svelte template` |
| `fix` | 修复 Bug | `fix: correct template path resolution` |
| `docs` | 文档 | `docs: update README` |
| `style` | 格式 | `style: format template files` |
| `refactor` | 重构 | `refactor: extract template rendering logic` |
| `test` | 测试 | `test: add svelte template tests` |
| `chore` | 工具 | `chore: update dependencies` |

### PR 流程

```text
1. Fork 仓库
2. 创建功能分支: git checkout -b feat/my-feature
3. 编写代码 + 测试
4. 确保测试通过: pnpm test
5. 确保类型检查通过: pnpm typecheck
6. 提交代码: git commit -m "feat: ..."
7. 推送: git push origin feat/my-feature
8. 发起 Pull Request
```

## 八、常见问题

### Q: 修改了代码但没生效？

A: 确认 `pnpm dev` 在运行（监听模式会自动编译）。或者手动执行 `pnpm build`。

### Q: 全局链接失效了？

A: 重新执行 `pnpm link --global`。或者直接用 `node /path/to/mirajay-cli/bin/cli.mjs` 运行。

### Q: 测试报错 "Cannot find module"？

A: 可能是 dist/ 没有构建。执行 `pnpm build` 后再跑测试。

### Q: 新增的模板文件被跳过了？

A: 检查 `shouldSkipFile()` 和 `shouldSkipEngineeringFile()` 的过滤逻辑，确认你的文件没有被过滤规则匹配到。

### Q: EJS 渲染结果不对？

A: 检查渲染上下文（`RenderContext`）中是否有你使用的变量。可以在 `generateProject()` 中添加 `console.log(context)` 查看完整的上下文。

## 九、代码风格

### 文件命名

- 命令文件：`kebab-case.ts`（如 `update-deps.ts`）
- 核心模块：`kebab-case.ts`（如 `engineering-manifest.ts`）
- 类型文件：`camelCase.ts` 或 `types.ts`
- 模板目录：`kebab-case`（如 `desktop-vue`）

### 代码组织

```text
每个命令文件的结构:
├── imports
├── 辅助函数（如果有）
├── defineCommand({
│     meta: { name, description },
│     args: { ... },
│     async run({ args }) {
│       1. banner()
│       2. 前置钩子
│       3. 核心逻辑
│       4. 后置钩子
│       5. 成功提示
│     }
│   })
└── export default
```

### 导出规范

- 命令文件：`export default`（默认导出 defineCommand 结果）
- 核心模块：具名导出（`export function xxx`）
- 类型：具名导出（`export interface Xxx`）
